# Task 01.5: Add Codeberg Forgejo Actions Build

You are adding a Codeberg/Forgejo Actions CI path for the T3 Code Flatpak build.

Goal: make this repository buildable from Codeberg using Forgejo Actions without changing the Flatpak package identity, sandbox posture, or provider/runtime scope. Keep the existing GitHub Actions workflow unless the maintainer explicitly decides to remove it.

Why this is a half-step:

- The Flatpak manifest and launcher already define the build artifact.
- The existing CI is GitHub-specific because it uses GitHub runner labels, GitHub contexts, and `flatpak/flatpak-github-actions`.
- Codeberg Forgejo Actions is familiar to GitHub Actions users, but it is not fully compatible. Treat the workflow as a separate CI target, not a blind copy.

Current repository files of interest:

- `.github/workflows/build.yml`
- `com.t3tools.t3code.yml`
- `Justfile`
- `tasks/README.md`

New files to add:

- `.forgejo/workflows/build.yml`

Required direction:

- Add a Forgejo Actions workflow that runs the same two build commands used locally:

```bash
flatpak-builder --force-clean --install-deps-from=flathub --repo=repo builddir com.t3tools.t3code.yml
flatpak build-bundle repo t3code.flatpak com.t3tools.t3code --runtime-repo=https://flathub.org/repo/flathub.flatpakrepo
```

- Keep the build x86_64-only unless upstream publishes a Linux aarch64 AppImage.
- Use a runner label that clearly documents the required environment, for example `flatpak-x86_64`.
- Use a Forgejo-compatible checkout action, preferably a fully qualified URL such as:

```yaml
- uses: https://code.forgejo.org/actions/checkout@v6
```

- Prefer direct `flatpak-builder` commands over the GitHub-specific `flatpak/flatpak-github-actions/flatpak-builder` action.
- Do not introduce release publishing, package signing, or upload credentials in this task.

Runner requirements:

- A self-hosted Forgejo runner connected to the Codeberg repository, user, or organization.
- Runner label matching the workflow's `runs-on` value, for example `flatpak-x86_64`.
- Linux x86_64 environment with:
  - `flatpak`
  - `flatpak-builder`
  - network access to Flathub and upstream AppImage URLs
  - enough permissions/user namespace support for `flatpak-builder`
- If the runner itself uses containers, configure the runner host deliberately for Flatpak builds. Do not assume GitHub's `container.options: --privileged` pattern is portable to Forgejo Actions.

Codeberg setup notes:

- Repository Actions are disabled by default on Codeberg and must be enabled under repository settings.
- Codeberg's hosted Forgejo Actions availability is limited. If the maintainer needs Codeberg-hosted CI without maintaining a runner, Woodpecker CI is the more appropriate Codeberg-hosted path.
- This task is specifically for Forgejo Actions support, so self-hosted runner setup should be documented as a prerequisite.

Security and scope:

- Do not add broad Flatpak permissions.
- Do not add `flatpak-spawn`.
- Do not grant host filesystem access in the Flatpak manifest.
- Do not add secrets to pull-request builds.
- Do not use `pull_request_target`.
- Avoid cache steps until the trust model for forked pull requests is reviewed.
- If later artifact upload or release publishing is added, use a separate task with explicit token scope and PR security review.

Suggested workflow shape:

```yaml
name: CI Build Flatpak

on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:

jobs:
  flatpak:
    name: Flatpak x86_64
    runs-on: flatpak-x86_64
    steps:
      - uses: https://code.forgejo.org/actions/checkout@v6

      - name: Build repository
        run: |
          flatpak-builder --force-clean \
            --install-deps-from=flathub \
            --repo=repo \
            builddir \
            com.t3tools.t3code.yml

      - name: Build bundle
        run: |
          flatpak build-bundle \
            repo \
            t3code.flatpak \
            com.t3tools.t3code \
            --runtime-repo=https://flathub.org/repo/flathub.flatpakrepo
```

Documentation requirements:

- Add a short README note explaining that Codeberg Forgejo Actions requires a self-hosted runner with Flatpak tooling.
- Mention Woodpecker as the practical alternative if hosted Codeberg CI is desired.
- Keep the existing local build commands documented through `Justfile`.

Validation:

- Validate workflow YAML syntax.
- On a configured Codeberg repository, push the workflow and verify the job is picked up by a runner with the configured label.
- Confirm the job produces `t3code.flatpak`.
- Confirm the manifest remains x86_64-only unless upstream has a Linux aarch64 AppImage.
